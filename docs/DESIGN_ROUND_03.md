# SMC 디자인 검토 03

## 피드백과 이번 범위

사용자는 2차 A/B가 기존안과 다르게 느껴지지 않고 여전히 정형적인 AI 홈페이지처럼 보인다고 평가했다. 2차의 배포·기능 검수 통과를 디자인 만족으로 간주하지 않는다. 이번에는 하나의 새 방향을 만들고 이전 A/B와 비교한다. 최종 디자인 선택과 전체 원페이지의 최종 공개는 별도 단계다.

## 구현 전 정한 구성

- 기준 레퍼런스: [Stayfolio 호텔 카라멜](https://www.stayfolio.com/findstay/hotel-karamel). 실제 Chrome 화면에서 큰 공간 사진과 작은 주변 UI, 공간 선택과 예약 정보의 연결을 확인했다. 홈페이지 복제나 사진 사용은 하지 않는다.
- 대표 사진: 보유한 실제 Room 5 C6 사진. 피아노와 공간이 함께 보이는 구도를 유지한다. 모든 방이 같은 규모라는 오해를 줄이도록 사진의 방 번호와 별도 개인 연습실 안내를 표시한다.
- PC 첫 화면: 전체 폭의 사진 위에 메뉴와 우측 제목. 피아노를 제목으로 덮지 않는다.
- 모바일: 310px 높이의 실제 사진 다음에 어두운 바탕의 제목·이동 링크. PC 사진을 세로로 과도하게 잘라 피아노가 사라지지 않게 한다.
- 태블릿 701–1000px: 검수에서 사진·제목 겹침을 발견해 430px 사진 아래로 제목과 안내를 분리했다.
- 두 번째 화면: 큰 사진 옆에 Room 1 / 3 / 5 선택 목록. 선택한 방의 사진·설명·예약 경로가 함께 바뀐다. 요금은 항상 30분 단위로 표시한다.
- 공간명·실제 악기·가격·위치를 우선한다. 장식용 영어와 큰 감성 슬로건을 줄인다.
- 색상: 실제 사진의 우드 톤 + 본문 바탕 #F8F7F3 + 어두운 녹색 #17241F. 한글은 운영체제 고딕을 사용한다.

## 도구와 구현

Figma의 기존 비교 파일에 편집 가능한 텍스트·레이아웃으로 첫 화면 초안을 만들었다. 이어진 스크린샷 호출은 Starter 플랜의 MCP 도구 호출 한도로 실패했다. 유료 전환을 하지 않았다. Figma 초안을 검수 완료된 디자인 원본으로 주장하지 않으며, 실제 웹 화면은 허용된 Chrome에서 별도로 검수한다.

웹 원본은 src/design-c.html, src/design-c.css, src/design-c.js다. build.mjs가 검토용 public/design/c.html과 CSS·JS를 생성한다. 기존 A/B는 같은 검토 배포 안에서 비교할 수 있다.

방 선택은 키보드 방향키·Home·End로 조작하며 선택 상태와 연결된 패널을 접근성 속성에 표시한다. JavaScript가 없는 경우 세 방의 사진·설명과 기본 앵커가 모두 남는다. 요금표는 브라우저 기본 details 요소이며, 메뉴의 요금 링크를 누르면 펼쳐진다.

확정 사진·요금·전화·예약 링크는 기존 content/site.json을 사용한다. publish는 false로 유지한다. 배포 URL과 실제 검수 범위는 NEXT_SESSION.md의 최신 기록을 따른다.

## 2026-09-17 완성도 개선

사용자가 현재 방향을 유지하며 개선을 계속하도록 요청했다. 첫 화면의 사진·색상과 공간 선택 구조를 유지하고 다음을 반영했다.

- 모바일 본문·요금 단위의 글자와 터치 영역 확대, 줄바꿈·여백 정리.
- 공간·사진 / 요금표 / 오시는 길 바로 이동. 선택 방을 표시하는 하단 버튼과 C6 전화 문의 전환·일반 방 네이버 경로 복원.
- 방 사진의 원본 비율 보존, 기본 dialog를 이용한 사진 확대·닫기, 키보드 복귀. 기존 사진 링크는 스크립트가 없을 때도 원본으로 연결한다.
- 확정 FAQ 다섯 개를 같은 페이지에 추가. 기존 확정 주소의 복사 버튼과 결과 안내.
- 외부 폰트·추적 코드·새 패키지를 추가하지 않았다. 실사진을 생성하거나 임의로 보정하지 않았다. 주 사진 원본은 가로 1,000px이므로 고해상도 촬영본 확보는 향후 시각 품질 개선 항목이다.
